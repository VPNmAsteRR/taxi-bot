# TAXIDRIVE24/7 — Telegram-боты для заказа такси

Лёгкий диспетчер без карт, платежей и сторонних сервисов:

- **пассажирский бот** — пассажир указывает «откуда / куда», видит тариф и базовую стоимость, проверяет заказ и нажимает **«Отправить водителям»**;
- **водительский бот** — водитель видит заказ и нажимает **«Взять заказ»**;
- после принятия заказ сразу исчезает у остальных водителей;
- пассажиру тут же приходит имя водителя, марка, цвет, номер машины и телефон (если указан);
- в обоих ботах есть **админка** со статистикой: водители на смене, заказы, выручка.

База — один SQLite-файл. Запуск — один процесс, который параллельно опрашивает
два бота. Внешние библиотеки не нужны: Python 3.10+ и стандартная библиотека.

## Как выглядит сценарий

### Пассажир

1. `/start` → **«🚕 Заказать такси»**.
2. Бот спрашивает **откуда** и **куда**.
3. Показывает карточку: адреса, тариф, базовая стоимость, номер заказа.
4. Пассажир нажимает **«✅ Отправить водителям»**.
5. Видит «Ищем для вас машину…» и может отменить заказ, пока его не приняли.
6. После принятия карточка меняется на данные машины:

```
✅ Машина найдена!

Заказ #0001
🚖 Водитель: Иван
🚗 Машина: Kia Rio, белый
🔢 Номер машины: А123ВС77
📞 Телефон: +79990000001
```

### Водитель

1. `/start` → **«📝 Зарегистрироваться»**.
2. Указывает имя, марку/модель, цвет, номер машины и телефон (телефон можно пропустить).
3. Получает заказы, когда включает приём заказов кнопкой **«🟢 Начать работу»**.
4. Нажимает **«🚖 Взять заказ»**.
5. Его карточка превращается в «Вы взяли заказ», появляется кнопка
   **«🏁 Завершить заказ»** и ссылка «💬 Написать пассажиру».
6. У всех остальных водителей это сообщение **удаляется**.

## Почему заказ не может принять два водителя

Принятие — один атомарный SQL-запрос:

```sql
UPDATE orders
SET status='accepted', driver_id=?, accepted_at=?
WHERE id=? AND status='searching';
```

Меняется ровно одна строка. Второй водитель получает «Этот заказ уже взяли».
После этого сообщения с заказом удаляются у остальных водителей, а если
рассылка ещё продолжалась — новые карточки уже не отправляются.

## Быстрый старт

### 1. Создайте двух ботов

В Telegram откройте **@BotFather**:

1. `/newbot` → например, `TAXIDRIVE24/7 Пассажир` → получите первый токен.
2. `/newbot` → например, `TAXIDRIVE24/7 Водитель` → получите второй токен.

Это должны быть **два разных бота**: у пассажира и водителя разные чаты и разные
истории сообщений.

### 2. Настройте `.env`

```bash
cd taxi-bot
cp .env.example .env
nano .env
```

Минимум:

```dotenv
PASSENGER_BOT_TOKEN=123456789:AA...
DRIVER_BOT_TOKEN=987654321:BB...
BASE_FARE=250
INCLUDED_KM=2
PRICE_PER_KM=50
DRIVER_INVITE_CODE=TAXiDrivEE
ADMIN_INVITE_CODE=TAXI-ADMIN-2026
```

Для боевого запуска обязательно задайте `DRIVER_INVITE_CODE` — иначе любой, кто
найдёт водительского бота, сможет зарегистрироваться и видеть адреса пассажиров.
Код чувствителен к регистру: символы должны совпадать точно.
`ADMIN_INVITE_CODE` тоже чувствителен к регистру и даёт доступ к админке. Замените
временный код `TAXI-ADMIN-2026` на свой перед передачей бота клиенту.

### 3. Запустите

```bash
python3 bot.py
```

Проверка:

1. В **водительском** боте: `/start` → регистрация.
2. В **пассажирском** боте: `/start` → заказ.
3. Нажмите «Отправить водителям» — карточка придёт водителю.
4. Нажмите «Взять заказ» — пассажиру придут данные машины.

Токены можно передать и флагами:

```bash
python3 bot.py \
  --passenger-token '123:AA...' \
  --driver-token '456:BB...' \
  --base-fare 250 \
  --included-km 2 \
  --price-per-km 50 \
  --data-dir ./data
```

## Настройки

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `PASSENGER_BOT_TOKEN` | — | токен пассажирского бота |
| `DRIVER_BOT_TOKEN` | — | токен водительского бота |
| `BASE_FARE` | `250` | стоимость посадки, ₽ |
| `INCLUDED_KM` | `2` | сколько км входит в стоимость посадки |
| `PRICE_PER_KM` | `50` | цена каждого начатого км сверх включённых, ₽ |
| `DRIVER_INVITE_CODE` | пусто | код доступа к регистрации водителей |
| `ADMIN_INVITE_CODE` | пусто | код входа в админку; пусто — админка отключена |
| `DATA_DIR` | `./data` | папка с `taxi.db` |
| `API_BASE` | `https://api.telegram.org` | адрес Bot API (для локального сервера) |

### Тариф

При настройках по умолчанию в карточке заказа показывается:

```text
Стоимость: от 250 ₽
Тариф: 250 ₽ посадка, 2 км включены, далее 50 ₽/км
```

Бот **не спрашивает у пассажира километраж**. Он показывает базовую стоимость и
условия тарифа, а доплата за километры сверх включённых считается по факту.
Если нужно, чтобы бот сам считал итоговую цену по адресам, потребуется
подключение карт и геокодинга.

### Админка

Админка доступна в **обоих** ботах:

- команда `/admin`;
- кнопка **«⚙️ Админка»** в главном меню, если пользователь уже админ.

Первый вход: `/admin` → введите `ADMIN_INVITE_CODE`. После этого пользователь
попадает в админку и видит:

- водителей на смене, на заказе и свободных;
- заказы в поиске и в поездке;
- заказы, завершённые и отменённые за сегодня;
- выручку по посадкам за сегодня;
- список водителей на смене и последние заказы.

Код можно передать нескольким людям — каждый, кто введёт его в `/admin`,
станет администратором. Чтобы закрыть доступ, смените `ADMIN_INVITE_CODE` и
перезапустите бота; уже добавленные админы останутся в базе.

## Файлы и база

```
taxi-bot/
  bot.py          — оба бота, регистрация, меню, обработка кнопок
  admin.py        — тексты и кнопки админки
  core.py         — заказы, тариф, рассылка, карточки, принятие/завершение
  store.py        — SQLite: пользователи, водители, заказы, админы, сессии
  tgapi.py        — минимальный клиент Telegram Bot API
  tests/          — тесты сценариев без Telegram
  data/taxi.db    — база (создаётся сама)
```

База хранит:

- пассажиров и водителей;
- заказы, тариф и их статусы (`searching`, `accepted`, `completed`, `cancelled`);
- администраторов;
- ID сообщений, чтобы удалить заказ у остальных водителей;
- незаконченные диалоги (регистрация, ввод адресов) — можно перезапустить бота
  без потери состояния.

Не запускайте два процесса с одними токенами: Telegram отдаст одному из них
ошибку `409 Conflict`. Для одного сервера это нормально.

## Тесты

```bash
cd taxi-bot
python3 -m unittest discover -s tests -v
```

Тесты проверяют:

- заказ получает один водитель, второй — нет;
- карточка удаляется у остальных;
- пассажир получает марку/цвет/номер;
- отмена заказа и гонка двух принятий;
- регистрацию водителя и полный сценарий через обработчики ботов;
- показ тарифа в карточке заказа;
- вход в админку в обоих ботах.

## Docker

```bash
cd taxi-bot
cp .env.example .env
nano .env
docker compose up -d --build
docker compose logs -f
```

`compose.yaml` хранит базу в именованном томе `taxi-data` (внутри — `/data`),
контейнер работает без лишних привилегий и без открытых входящих портов.

Посмотреть/скопировать базу:

```bash
docker compose exec taxi-bot ls -l /data
docker compose cp taxi-bot:/data/taxi.db ./taxi.db
```

## systemd на VPS

```bash
sudo useradd --system --home /opt/taxi-bot --shell /usr/sbin/nologin taxi
sudo mkdir -p /opt/taxi-bot /var/lib/taxi-bot
sudo cp bot.py admin.py core.py store.py tgapi.py /opt/taxi-bot/
sudo chown -R root:root /opt/taxi-bot
sudo chown -R taxi:taxi /var/lib/taxi-bot

sudo cp .env.example /etc/taxi-bot.env
sudo nano /etc/taxi-bot.env       # токены, код, DATA_DIR=/var/lib/taxi-bot
sudo chmod 600 /etc/taxi-bot.env

sudo cp deploy/taxi-bot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now taxi-bot
sudo journalctl -u taxi-bot -f
```

## Ограничения и что можно добавить дальше

Это сознательно лёгкий MVP, а не полноценная CRM такси:

- нет карты и автоматического расчёта итоговой цены по адресам — бот показывает
  тариф и базовую стоимость;
- нет онлайн-платежей;
- нет автоматического снятия заказа по таймауту, если водители не откликнулись;
- админка показывает статистику, но не проверяет документы и не блокирует
  водителей;
- пассажир не оставляет телефон — связь идёт через Telegram (кнопка
  «Написать пассажиру» у водителя);
- один процесс и SQLite рассчитаны на небольшой городской парк; для многих
  тысяч заказов нужен PostgreSQL и очередь.

Ближайшие полезные шаги: таймаут заказа, уведомление пассажира «сейчас все
машины заняты», отмена принятого заказа водителем с возвратом в пул,
автоматический расчёт цены через карты и сбор телефона пассажира.
